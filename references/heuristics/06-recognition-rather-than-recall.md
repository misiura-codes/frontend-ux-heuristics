# H6 Recognition Rather Than Recall

Use when the UI includes navigation, menus, filters, search, settings, multi-step flows, hidden state, cross-screen dependencies, dense data tools, comparison, saved items, history, gestures, or returning-user workflows.

## Check

- Keep labels, options, and required context visible or easy to retrieve.
- Do not force users to remember values from previous screens.
- Show selected filters, current object, prior choices, and next steps.
- Prefer visible menus, examples, suggestions, and previews over memorized commands.
- Put contextual help close to the field, decision, or action it explains.
- Externalize working memory: keep task-critical information available as a visible summary, side panel, comparison table, history, or saved list.
- Use cues that exploit practice, recency, and context: recent items, past searches, defaults, examples, and familiar labels.
- Avoid relying on onboarding tutorials for information users need later; provide just-in-time cues in the live context.

## Recognition Cues

- Show choices as selectable options instead of requiring users to generate terms or commands from scratch.
- Use search suggestions, autocomplete, recent searches, and query examples to reduce recall during search.
- Label icons until users have enough exposure to recognize them confidently.
- Add signifiers, labels, or contextual tips for gestures and hidden commands.
- Preserve previous choices in multi-step flows and expose them where later decisions depend on them.

## External Memory

- Provide comparison tables, saved items, wish lists, pinned candidates, scratchpads, or side-by-side summaries for evaluation tasks.
- Keep important source information visible on small screens where users cannot easily glance back.
- Show recent pages, recently viewed items, drafts, and in-progress tasks to help users resume.
- Let users save, park, or mark candidates without interrupting their current task.
- Do not make users copy IDs, values, dates, rules, or object names between screens.

## Just-in-Time Help

- Provide assistance exactly where and when confusion is likely.
- Keep help short, task-specific, and tied to the current state.
- Prefer inline text, examples, placeholder guidance, tooltips, coach marks, or empty-state examples over separate documentation.
- Reveal advanced or secondary explanation only when requested or contextually relevant.

## Evidence

Look for persistent breadcrumbs, visible active filters, step summaries, remembered recent choices, recently viewed items, search history, examples in empty states, combobox suggestions, comparison tables, saved candidates, contextual tips, labeled icons, and inline helper text.

## Failure Patterns

- Users must remember an ID, status, or rule from another page.
- Icon-only controls have no label or accessible name.
- A wizard hides earlier choices but depends on them later.
- Search syntax must be memorized before basic searching works.
- A tutorial explains behavior once, but the live UI provides no cues when users need it.
- Users must compare items by opening many tabs or taking notes because the UI offers no external memory.
- Small-screen layouts hide context needed to understand the current task.
- Gesture-only interactions require users to remember hidden actions.
- Returning users cannot retrace recent pages, searches, drafts, or viewed items.
