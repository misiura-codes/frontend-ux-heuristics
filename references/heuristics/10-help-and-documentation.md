# H10 Help and Documentation

Use when the UI includes complex setup, rare workflows, onboarding, permissions, imports, integrations, advanced settings, troubleshooting, redesigned UI, technical concepts, support docs, in-product search, help search, or large information spaces.

## Check

- Make the interface usable without documentation where possible.
- Provide contextual help at the moment of need.
- Keep proactive help concise, relevant, dismissible, and retrievable later.
- Favor pull help triggered by user context over broad push overlays.
- Make reactive help searchable, task-focused, concrete, and step-based.
- Link from compact in-product help to fuller documentation when needed.
- Do not explain obvious controls or use documentation to compensate for avoidable interface confusion.
- Keep help content scannable with clear headings, chunks, keywords, examples, and numbered steps.
- Provide both text and visual/video help for complex tasks; do not make video the only source.
- Make search visible and simple when users may be lost or looking for specific help.

## Proactive Help

- Use proactive help for new users, novice users building proficiency, and existing users facing a redesigned interface.
- Prefer pull revelations tied to the current task, role, object, field, or flow.
- Use push revelations only for broadly relevant information; make them skippable, dismissible, and available later.
- Keep tutorials, tooltips, coach marks, templates, and wizards short and action-oriented.
- Avoid onboarding that teaches standard patterns users already understand.

## Reactive Help

- Provide detailed troubleshooting, FAQs, docs, training, or tutorials when users actively seek help.
- Start with a short overview, then give concrete steps, prerequisites, outcomes, and examples.
- Define technical terms and patterns before relying on them.
- Categorize help by task, topic, user type, product area, or problem state.
- Highlight top, common, or recommended articles when the help library is large.
- Link from errors, empty states, permission blockers, imports, and setup steps to the relevant help topic.

## Search and Findability

- Put search where users expect it and keep it available from pages where users may get lost.
- Prefer a visible search input over a hidden search link for complex sites, docs, and home/help pages.
- Make the input wide enough for typical queries and label it plainly.
- Optimize for short, simple queries and strong first-result quality; do not rely on users reformulating searches.
- Avoid advanced search on entry pages; offer it from results only when simple search fails.
- Default scoped search to all content unless the scope is obvious; show the active scope and provide one-click scope expansion.
- Provide useful no-results recovery: suggestions, spelling help, broader scope, categories, or contact path.

## Evidence

Look for contextual tooltip or help drawer, setup checklist, searchable docs link, visible help search box, categorized help topics, top articles, clear "learn more" from an error, import template, examples, text alternatives for video, scannable numbered steps, and dismissible onboarding.

## Failure Patterns

- A tutorial explains obvious controls.
- Help interrupts the task and cannot be skipped.
- Documentation is high-level marketing copy instead of concrete steps.
- Help content exists only once at onboarding and cannot be found later.
- Documentation compensates for avoidable interface confusion.
- Documentation is comprehensive but hard to search, scan, or categorize.
- Help search is hidden behind a link, too narrow, scoped unexpectedly, or weak on common first queries.
- Advanced search or Boolean syntax is required before basic help search works.
- Search results do not show the most likely answer on the first page.
- Video-only help forces users to watch instead of scanning text instructions.
- No-results pages give no suggestions, broader search option, or escalation path.
